## 3. Как обновлять / деплоить

- **Проще всего (без командной строки):** зайти на vercel.com под аккаунтом → перетащить папку проекта на vercel.com/new → Deploy. Обновление — так же заново.
- **Через CLI:** `npm i -g vercel` → `cd` в папку проекта → `vercel --prod`.
- **Рекомендуется для регулярных правок:** залить папку в GitHub-репозиторий и подключить его к проекту Vercel — деплой автоматический при каждом пуше.

## 4. Данные

- Хранятся в **localStorage браузера** (ключ `set-db-v3`), **у каждого пользователя своя копия**. Общего сервера/базы нет.
- Бэкап и перенос — кнопки **экспорт/импорт** (один JSON-файл).
- **Важно:** чтобы у команды была единая общая база — следующим шагом нужен бэкенд (Supabase/Postgres) + авторизация. Сейчас это пилот на localStorage.

## 5. Архитектура (для того, кто примет)

- Данные-заготовка — в функции `seed()`: 9 команда (флаг `ours`) + 7 внешних контактов, связи + авто-сетка команды (`addTeamLinks`).
- Модель: `person {id, name, role, company, contact, ours, notes}`, `link {id, a, b, type, strength, date, note}`.
- Граф — force-directed на canvas (функции `tick` / `draw` / `fitView`).
- Версионирование данных (`LS_KEY` + `TEAM_MESH_V` + `reconcileSeed` / `upgradeTeam`): при обновлении кода недостающие люди/связи до-заливаются в сохранённые данные пользователя без потери его правок.
- Поле «Контакт» есть в форме/списке/карточке; сейчас пустое, заполняется вручную.
